为什么新的检查真的起作用

以下不是“跑过一次”的描述，而是每个 oracle 能杀死的具体错误实现。

AI trace 异常闭合

移除 service span 会丢失统计 key；恢复裸 Enter/Exit 会在异常路径留下未闭合 frame。两种 mutation 都会使测试失败。

Contingency 执行中状态

observer 位于正式伤害 resolver 内部。历史“先伪装已学、结算后 finally 恢复”的实现会在中途被看到，前后快照无法蒙混。

TestExit 请求事实

错误 reason、退出码、label 或 passed 映射会直接改变 coordinator 捕获到的 FirstRequest，不是检查构造函数文本。

真实 autoload 与 snapshot

交换 SceneTree 中 coordinator/session 顺序、借用错误 epoch、复制 skills index 或丢失 borrower 登记，都会触发现有断言。

挑衅 typed 数值

任意等级出现非零攻击加值会由 GetEffectiveAttackRollBonus(level) 直接暴露；资源里是否省略默认字段不再是 oracle。

Tuner 共享数据 owner

目录重复/非法边界由 loader 拒绝；任一路径未被 C# definition 或 OverrideApplier 支持会失败。测试解析 JSON 结构，不读取 Python/C# 源码找 token。

AI 未学习技能反例

若 evaluator 绕过 available skill entry、直接把 authored skill id 组装为命令，未知技能会产生 decision，反例立即失败。

Barrier 事件结果

少报法球区域格、传送只报新格或只报旧格，都会改变 BattleEventBatch.ChangedCoordsTyped 的真实观察结果。
