# 伐木工之斧武器重设计

日期：2026-07-10
状态：待用户复核
来源：`docs/design/weapons/by_family/axes_02.md:59`

## 设计目标

伐木工之斧原设计只有面对植物生物时才提供直接战斗收益，快速砍伐依赖当前不存在的常规砍树行动，树的愤怒还会在使用核心能力后强化敌人。它与同档专属武器相比缺少普通战斗中的稳定循环。

重设计后，伐木工之斧应成为一把通用的连续劈砍战斧：持续攻击同一目标时越砍越准，并在第三次命中形成一次倒木重劈；面对植物生物时保留原设计的额外伤害优势。它不依赖主动技能、每日次数或战场必须包含森林。

## 武器来源

- 名称：伐木工之斧
- 内部物品 id：`weapon_unique_battleaxe_lumberjack_383`
- 武器族：斧
- 基础物品：`weapon_type_battleaxe_base`
- 训练组：军用
- 射程：近战 1 格
- 单手伤害：`1D8+2`
- 双手伤害：`1D10+2`，来自战斧的多用属性
- 属性：多用
- 原始价格：22000
- 重设计价格：32000
- 原始特殊性质：
  - 快速砍伐：砍伐树木速度为正常速度的三倍。
  - 植物杀手：对植物类型生物额外造成 `2D6` 伤害。
  - 树的愤怒：在森林中每砍伐一棵树，敌对植物生物攻击持有者时获得 `+1`。

价格提高到 32000，因为新版在普通战斗中的强度已接近屠夫和猎人之斧，不再是只对少数目标生效的低价特攻武器。

## 重设计总览

新版包含三条能力：

1. 顺纹连斩：连续命中同一目标时叠加劈痕，并获得递增命中加值。
2. 植物杀手：真实武器命中植物目标时追加 `2D6` 挥砍伤害。
3. 倒木重劈：攻击命中前已有 2 层劈痕的目标时追加 `2D8` 挥砍伤害，并在本次命中结算后清除劈痕。

原树的愤怒不保留。它既依赖当前不存在的常规砍树事件，又会让武器的使用收益与风险倒挂；倒木重劈取代它，承担连续劈砍循环的终结效果。

## 特性设计

### 顺纹连斩

伐木工之斧每次真实武器攻击命中后，目标获得 1 层劈痕。劈痕持续 `120TU`，再次命中时刷新持续时间，最多 3 层。

攻击同一目标时，根据命中检定前该持有者留下的劈痕层数获得命中加值：

- 0 层：无加值。
- 1 层：命中检定 `+1`。
- 2 层：命中检定 `+2`。

内部状态：

- 状态 id：`lumberjack_chop_notch`
- 持续时间：`120TU`
- 叠层方式：增加并刷新持续时间
- 层数上限：3
- 来源：记录当前拥有这组劈痕的战斗单位 id

只有这把斧参与结算的真实武器伤害能够施加劈痕。未命中不会叠层或刷新持续时间；纯法术、徒手攻击和其他武器不会叠层。

同一目标同一时刻只保留一组劈痕。若另一名伐木工之斧持有者命中该目标，劈痕来源转移给新持有者，层数重置为 1，而不是继承原持有者的层数。这样符合当前状态集合的唯一 `status_id` 所有权，同时保证不同持有者不能互相借用连斩进度。

### 植物杀手

伐木工之斧真实武器攻击命中生物分类包含 `plant` 的目标时，额外造成 `2D6 physical_slash` 伤害。

该伤害：

- 与顺纹连斩和倒木重劈同时生效。
- 使用正式 `creature_type_tags` 判断目标，不回查敌人模板。
- 走通用 `add_damage_dice` 结算，沿用现有暴击、减伤和伤害事件语义。
- 不对缺少 `plant` 标签的目标生效。

### 倒木重劈

当攻击命中前，目标已经有该持有者留下的 2 层劈痕时，本次真实武器命中额外造成 `2D8 physical_slash` 伤害。

本次命中的完整顺序为：

1. 命中检定读取命中前的 2 层劈痕，获得 `+2`。
2. 命中后追加 `2D8` 倒木重劈伤害。
3. 本次命中正常增加第 3 层劈痕。
4. 达到 3 层后立即消耗全部 3 层。

因此标准循环为：

```text
第一击：基础伤害，留下 1 层劈痕
第二击：命中 +1，留下 2 层劈痕
第三击：命中 +2，基础伤害 +2D8，清空劈痕
```

第三击未命中时不追加伤害、不增加层数、不消耗已有 2 层，后续攻击仍可尝试完成倒木重劈。若第三击命中植物目标，则 `2D8` 倒木重劈与 `2D6` 植物杀手同时结算。

## 强度基准

对普通目标，完整三次命中循环额外造成一次 `2D8`，平均约每次命中增加 3 点骰伤；第二次和第三次攻击还分别获得 `+1`、`+2` 命中。这使它在持续攻击同一目标时达到霜咬一档的通用战斗收益，但没有霜咬的减速控制。

对植物目标，每次命中再追加 `2D6`，第三击同时触发 `2D6+2D8`。植物杀手仍是明显优势，但不再是整把武器唯一的战斗价值。

## 机制分类

- 物品基础伤害、射程和价格：当前 `ItemDef` 支持。
- 植物杀手：当前装备能力的生物分类 fact 与 `add_damage_dice` 支持。
- 劈痕状态、叠层、持续时间和消费：当前 `apply_status`、`status_stacks` 与 `consume_status_stacks` 支持。
- 按劈痕层数提供命中加值：当前 `attack_roll_bonus` 支持。
- 来源隔离：需要新增通用 fact `source_bound_status_stacks`。它读取指定目标状态的层数，但只有状态的 `source_unit_id` 与当前装备能力来源单位一致时才返回层数，否则返回 0。
- 不新增主动 `SkillDef`，不新增武器专用 C# 分支，不使用武器 id 或 trait id 推导运行时行为。

`source_bound_status_stacks` 应作为通用 typed fact 注册、校验并由装备能力运行时解析，可供以后所有需要来源隔离叠层的装备能力复用。

劈痕叠加使用两条互斥的配置动作，并按以下顺序解析：

1. `source_bound_status_stacks >= 1` 时使用 `add`，为当前来源增加 1 层。
2. `source_bound_status_stacks == 0` 时使用 `refresh`，把无来源或其他来源的旧劈痕重置为当前来源的 1 层。

第三击随后通过现有 `consume_status_stacks` 且 `require_source_unit_match = true` 消耗 3 层。这个顺序让同一来源正常累加，也让来源变化时可靠地从 1 层重新开始。

## 内容模型

实现内容包括：

- 物品：`data/configs/items/weapon_unique_battleaxe_lumberjack.tres`
- Trait：
  - `weapon.axe.lumberjack.chopping_rhythm`
  - `weapon.axe.lumberjack.plant_slayer`
  - `weapon.axe.lumberjack.felling_blow`
- 装备能力包：`data/configs/equipment_abilities/lumberjack_axe_pack.tres`
- 回归：`tests/battle_runtime/runtime/run_lumberjack_axe_weapon_ability_regression.cs`

Trait 只负责身份和装备能力来源；触发、条件、伤害、状态和消费全部由装备能力包配置。

## 生命周期与边界情况

- 劈痕持续 `120TU`，再次命中刷新；超时后自然清除。
- 目标死亡时其劈痕随目标状态清理。
- 战斗结束时所有战斗状态清理，不写入角色或装备存档。
- 卸下或摧毁伐木工之斧后，装备能力来源立即消失；目标上尚未到期的劈痕可以保留为无效显示状态，但不能再提供命中加值、倒木重劈或植物杀手伤害。
- 重新装备后，只有来源单位匹配且仍在 `120TU` 内的劈痕可再次被读取。
- 多个持有者攻击同一目标时，后命中的持有者接管劈痕并从 1 层开始；原持有者不能继续读取或消费该组劈痕。
- 攻击被闪避或未命中时不叠层、不刷新、不消费。
- 命中但最终 HP 伤害为 0 时仍视为斧刃命中并推进劈痕；倒木重劈骰照常进入伤害结算，由减伤和屏障决定实际 HP 伤害。

## 用例与测试

回归必须通过真实装备投影和攻击结算路径覆盖：

- 内容注册表加载物品、三个 trait 和三个 binding。
- 装备后投影 `1D8+2` 单手、`1D10+2` 双手、射程 1、多用属性和装备能力来源。
- 卸装后武器投影、trait、binding 和派生收益全部消失。
- 第一次命中留下 1 层、第二次命中留下 2 层、第三次命中触发 `2D8` 后清层。
- 第二次攻击命中 `+1`，第三次攻击命中 `+2`，清层后下一次攻击回到 `+0`。
- 劈痕持续时间精确为 `120TU`，命中刷新，超时清除。
- 第三次攻击未命中时保留 2 层，且不触发 `2D8`。
- 命中植物目标时每次追加 `2D6`；普通目标不追加。
- 植物目标第三击同时结算基础武器伤害、`2D6` 植物杀手和 `2D8` 倒木重劈。
- 其他武器、徒手攻击和不含真实武器伤害的技能不会叠层或触发能力。
- 两名持有者攻击同一目标时，第二名持有者命中后应把劈痕来源切换为自己并重置为 1 层；第一名持有者不能借用该层数。
- 卸装后残留劈痕不能继续提供命中或伤害收益。
- 脚本目录中不存在伐木工之斧 item id、trait id 或 binding id 的硬编码分支。

## 项目上下文影响

本设计沿用 CU-10、CU-13、CU-15、CU-16 和 CU-19 的现有职责。新增 `source_bound_status_stacks` 只是装备能力通用 fact 的扩展，不改变系统所有权或推荐装载关系，因此 `docs/design/project_context_units.md` 无需更新。
