# 技能强度评估机制 v1

本规范用于技能设计、优化与内容审查。它是已接入技能设计流程的作者工具规范，不是新增战斗运行时，也不宣称已有全职业、全阶段的平衡合格区间。

## 1. 固定基准，局部评估

每次评估读取本规范、目标技能的实际等级定义、对应机制的证据和 **1–3 个同职责、同成长阶段的已审查基准记录**。不重新扫描全部技能、全部敌人或所有战斗系统。

- 时间规则及其版本保存在 `.codex/skills/design-godot-skill/assets/power-assessment/baseline.json`。标准时间单位为 40TU；30/20TU 是敏感性场景，不表示全体单位都按这些间隔行动。
- 当前时间源由 `ActionCadenceContentRules`、`BattleUnitActionClockState`、`BattleUnitCooldownState`、`BattleTimelineDriver`、`BattleRuntimeSkillTurnResolver` 拥有。工具只校验这五个显式文件的归一化文本 SHA256，不解析或搜索其他源码。
- 机制证据与候选数据的依赖由评估输入 `source_sha256` 显式固定。正式 preview/实测输入必须包含依赖及证据文件指纹；设计假设可为空，但必须标为 `controlled_assumption`。
- 指纹变化时输出 `baseline_stale` 或 `evidence_stale`，不继续产生可冒充当前证据的数值。先看受影响文件的差异，再更新对应基准版本；禁止只重算哈希以消除过期提示。
- 加入新状态、目标类型、反应或资源规则时，只扩展该机制的读集和场景。规则没变、只是单技能数值变化时，复用原场景与基准。

基准不是全技能平均数。已确认有问题的旧技能、未批准方案、仅能通过 schema 的内容，都不能自动成为“正常强度”的锚点。

## 2. 分开三个问题

| 问题 | 判定依据 | 输出 |
|---|---|---|
| 内容是否合法、是否兑现承诺 | strict JSON、Definition、执行/preview/HUD/AI 一致性及行为回归 | 合法/不合法；实现/缺失/描述错误 |
| 可获得多少收益、付出多少代价 | 固定场景、逐事件边际结果、行动量化、资源预算 | 可复算指标与适用条件 |
| 这些收益是否适合该技能定位 | 同职责、同阶段、同投入基准；完整战斗证据 | 偏弱/区间内/偏强/角色不同/证据不足 |

禁止用“通过资源校验”代替后两项。`growth_tier` 的 60/120/180/240 是永久属性成长预算，**不是战斗威力系数**；非核心上限和绝对上限也不是简单伤害倍率。

## 3. 一张技能输入卡

每项设计只补齐以下信息，后续修改更新差异：

1. 版本、技能 ID、实际等级、职责、习得阶段、核心/非核心条件、获取成本、学习/战斗槽位。
2. 目标、范围、实际可命中数量、敌我伤害、武器/视线/认知/状态前置条件。
3. AP、MP、体力、斗气、施法时间、冷却、持续时间、次数、反噬和维持成本。资源分别列出，不用任意兑换率相加。
4. 单次效果的条件与边际结果；证据来自设计假设、canonical preview 或正式运行，必须区分。
5. 对应角色基准及场景版本；尚无已校准同类基准时直接标“未校准”，保留指标，不强行下强弱结论。
6. 培养目标：习得等级、每级熟练度消耗、到非核心/晋升后上限的累计消耗、触发事实、每次奖励、去重单位、各等级有效事件频率，以及评级/训练/任务等额外来源。只写 trigger/amount 字段不算完成成长设计。

计算最少覆盖 0/1 级、每个机制断点、成长门槛和绝对上限。持续时间、适用范围、成本和冷却的联动必须一起重算；不能逐项看似合理后直接叠加。

## 4. 固定场景轴

下列数值是分析探针，不是玩家属性分布或已校准职业价格表。常规评估选一个中心场景、一个不利场景和一个机制边界场景；不默认全笛卡尔积。

| 轴 | 固定探针 | 用途 |
|---|---|---|
| 观察时长 | 80 / 160 / 320TU | 短战收益、持续收益、资源耗尽 |
| 施法者行动间隔 | 40 / 30 / 20TU | 冷却量化、行动机会成本 |
| 敌人行动间隔 | 40 / 30 / 20TU | 控制/防护覆盖的事件数 |
| 敌方压力 | 1 / 3 个敌人，每次 1 个攻击事件 | 单挑与被集火；连击单独列事件 |
| 普通命中率 | 35% / 60% / 85% | 低/中/高命中压力；不代替正式幸运/暴击模型 |
| 行动相位 | 最早 5TU / 一个完整间隔；同刻双方两种顺序 | 避免持续时间边界差一个行动 |
| 资源 | 相同的固定初始池、相同恢复政策 | 不能给贵技能按自身成本扩大资源池再比较续航 |

地图占位、人数、阵营、属性、装备、状态及 AI 政策随记录固定。范围技按“能实际覆盖的目标”计数，不能按几何最大格数计收益。条件收益必须展示条件成立与不成立两种结果，不凭感觉填写触发率。

## 5. 统一计量，保留收益向量

以场景内一项基准行动的实际预期伤害 `D_ref` 为 HP 效果的对照单位。正式评估从固定 actor/target 的 canonical preview 取得它；示例可假定数值，但不能作为内容价格标准。

| 职责 | 主指标 | 必须扣除或检查 |
|---|---|---|
| 输出 | 预期有效 HP 伤害、击杀概率、首次生效时间 | 命中/豁免/暴击/减伤、溢出伤害、友伤、目标提前死亡 |
| 防御 | 各次威胁施加前后预期伤害之差；存活概率变化 | 绕过攻击类型、优势抵消、已存在保护、未被攻击、驱散 |
| 治疗/护盾 | 有效治疗、失效前实际可吸收伤害 | 过量治疗、护盾互斥/替换、过期未消费、与减伤的先后顺序 |
| 控制 | 实际剥夺的敌方 AP/行动、推迟的关键行动 | 豁免/免疫、行动相位、解除、原本不能行动、控制重叠 |
| 增益/联动 | 有/无增益时完整效果的差值 | 触发前置、触发消耗、连锁递归、原本已有的效果 |
| 位移/地形 | 可执行位移、逃离/接敌/占点结果、由此改变的伤害 | 路径/占位、机会攻击、原本已有安全路线；不能按格数固定兑换伤害 |
| 召唤/反应 | 生命周期内实际行动与反应的净贡献 | 存活时间、触发次数、反应预算、维护/指挥、挤占己方行动 |

HP 各分项可分别除以 `D_ref`，称为“基准伤害行动等价”。控制 AP、位移格数、胜率仍保留独立维度，**不相加成一个万能总分**。同一次行动被控制取消后，不得又把它计入防护减伤；连锁与复施必须算完整链的边际差，不能把标签加成独立相乘。

简化防护探针可用 `单次减伤期望 = E[伤害前] - E[伤害后]`。若只看固定命中伤害、独立普通 D20 且无优势/特殊暴击门，才可用 `(p - p²) × 命中伤害` 演示劣势。正式结果沿用 `BattleHitResolver`/canonical preview，不在 Python 重写命中、幸运、暴击或豁免算法。

## 6. TU、循环与续航必须同时算

对于即时、无加速/控制/反应插队的普通主动施法，施法者行动间隔 `T`，冷却 `C`，持续 `D`：

```text
最早再次主动施法间隔 R = max(1, ceil(C / T)) × T
理想周期覆盖率 = min(1, D / R)
每周期空档 = max(0, R - D)
提前刷新重叠 = max(0, D - R)
```

`max(1, ...)` 是工具“每次激活至多施放一次”的固定政策；零冷却、多 AP 连发、装备反应和额外行动不能套用此政策来证明最大输出。

状态覆盖使用区间并集，不把刷新重叠部分重复计价。观察窗口和状态区间均取左闭右开；状态在到期同刻已失效，同刻新施法能否覆盖敌方事件由事件顺序决定。整数事件数取决于相位，不能只用 `D / T` 四舍五入。

上述为覆盖/行动算术口径。来源型持续伤害的正式 `BattleRuntimeSkillTurnResolver` 使用 `nextTickAtTu <= tickLimitTu`，会先结算恰好位于到期时刻的一跳，再衰减持续时间；提前结算燃烧必须使用该 runtime 规则，不能套用覆盖流的右开端点。对应局部证据见[熔爆术输入卡](mage_molten_burst.md)。

还要列出：首次覆盖、每次复施时刻、累计施放次数、AP 支出、每种资源支出、首次无法支付时间、整场覆盖率、付出同样 AP 原本能造成的输出。持续长于冷却只说明“时间上允许续上”，不保证法力、控制或真实行动安排支持常驻。

施法时间、维持、时间静滞、加速、恢复、死亡、位移改变目标集合等会破坏简化前提，转用正式 runtime 局部探针或 BattleSim。不得为让计算器接受而省略这些字段。

## 7. 如何得出强弱结论

固定记录里分别比较：**单次价值、首次生效、单位 AP 效率、单位稀缺资源效率、观察期总收益、持续覆盖、前置条件和反制面**。

- 同职责/同阶段/同场景下，若候选在所有相关收益与成本轴不差、至少一轴更好且没有额外限制，记录“支配现有基准”，进入强度审查；不自动判定需削弱。
- 中心场景优于基准，但不利场景有真实代价，可以形成有意义的专长；不能只展示最有利场景。
- 中心和专长场景都不如基准，且没有资源、获取或构筑优势，才支持“偏弱”的判断。
- 高阶技能的提升应对应它的用途及培养投入。不能用 `advanced` 直接批准更低费用、更长持续、更短冷却和更宽目标范围的组合。
- 角色合格区间来自已审查的锚点或固定场景实测；未校准时输出“证据不足/待校准”，不生成虚假的精确强度分。

锚点记录放在 `docs/reviews/skill_power/`（有实际记录时再创建），必须含场景、等级、输入/结果、源码依赖、审核结论和适用范围。新候选不能自行替换锚点。小样本只提供方向；模拟中无效、卡住和未完成的 run 不计入正常分母，仍需报告。

## 8. 当前可运行工具

```powershell
python .codex/skills/design-godot-skill/scripts/assess_skill_power.py .codex/skills/design-godot-skill/assets/power-assessment/blur-example.json
```

可用 `--output <path>` 保存 JSON。退出 0 只表示算术评估完成；1 表示输入不支持或错误；2 表示基准/输入证据过期。工具不运行游戏、不发现或改写技能、不运行数值 BattleSim，也不输出 balance PASS。

输入形状见完整示例。每个 case 声明：

- `duration_tu/cooldown_tu/costs`：即时技能参数；`max_casts` 可限制单次使用。
- `scenario`：观察时长、施法间隔、AP、固定资源池、基准输出、同刻顺序。
- `on_cast`：每次施放的有效边际效果向量；默认是条件成立且目标存活的受控上界，真实概率/目标必须在证据中交代。
- `streams`：有效期内的事件流、人数、周期、首次事件相位及每事件边际效果。增加恢复、位移等不支持字段会被拒绝，不会静默忽略。
- `basis/assumptions/source_sha256`：来源类别、明确前提和证据依赖。`canonical_preview` 只代表输入来源，不把该算术日程升级为真实战斗结果。

实现自动计算即时循环、资源限制、区间并集、逐事件收益、单次与整场分项、AP/MP 效率和行动机会成本。计算器没有处理施法中断、动态路径、AI 选择或完整伤害链；这些继续由现有正式引擎拥有。

## 9. 用幻身术复现本次问题

`blur-example.json` 固定六个受控案例，包括已撤回的距离门槛低等级方案、无距离门槛 6/7 级方案、只够施放一次的法力池、敌人较晚行动相位和短战。**这些是算术反例，不是批准的新资源或防御强度基准。**

在 40TU 施法间隔、320TU 观察窗、敌人 30TU 间隔且从 5TU 起行动、每个事件减少 2.4 预期 HP 的假设下：

- 7 级 `D=180/C=150` 的实际循环为 160TU，刷新有 20TU 重叠；资源足够时 0/160TU 两次施放覆盖整窗。
- 6 级 `D=150/C=150` 每次循环有 10TU 空档。不能因持续等于冷却就声称常驻。
- 相同 7 级只给 45MP 时只能施放一次；长期常驻结论不再成立。
- 较晚敌人相位会改变单次实际受影响的攻击数。持续 180TU 不能直接记为确定的 18 次攻击。
- 同时改变作用范围、持续、费用和冷却时，必须展示这些案例的分项差异，再与防御锚点比较。

## 10. 升级验证的门槛

常规数值调整：复用本规范、目标定义、已存机制结果及同类锚点，运行算术工具，按变化运行聚焦正确性回归。

新增机制、无限循环、时间/反应/召唤、强控制、多目标互相反馈、无法可靠估计条件概率：补正式局部探针；需要平衡结论时使用固定 BattleSim 场景。已有 `SkillGenerationBattleSimGate` 只覆盖敌对伤害技能，不能拿其 PASS 证明防御、治疗或辅助强度。它的标准对比阈值也不是全类型通用价格表。

完整模拟证据始终标明完成样本、失败/超时、AI 政策、实际施放次数与参数版本。数值模拟保持 opt-in，不进入普通全量正确性回归。

## 11. 熟练度与培养节奏联合评估

先明确用户希望到达哪个门槛、投入多少场正常战斗，再同时选择触发与曲线。不能保留旧曲线、只改一次奖励，也不能用单次施法强度代替每场练习量。

```text
本场直接熟练度 = Σ 实际合格且完成去重的事件奖励
本场入账总量 = 直接熟练度 + 实际领取的评级奖励 + 其他实际来源
从等级 a 到 b 的需求 = Σ mastery_curve[a:b] - 已有当前等级进度
固定每场入账 g 的场数估算 = ceil(所需熟练度 / g)
```

曲线项是“这一等级升下一级所需”，不是累计阈值。正式等级推进、来源许可和上限截断由 `ProgressionService` / `SkillEffectiveMaxLevelRules` 拥有，工具或作者表不能重定义其语义。不同等级有效事件数不同时，应逐级累计或使用完整有序奖励流；不要平均掉持续、资源和解锁差异。

每张成长记录必须给出：

- 何种事件代表实际练习；成功施放、攻击检定、伤害段、目标、反应、每场结算中的哪一个是去重单位。
- 零收益情况：空放、冗余状态、刷新、友军、豁免/必中、击中/未击中、过量治疗、预览等应分别明确，按该技能职责选择。
- 至少低/中/高三档有效事件频率与额外来源；频率来自作者假设或真实记录要标清。防御型不能假定每名敌人永远攻击自己，成长也不应依赖事后猜测“原本必定命中”。
- 全局奖励的独立性：幻身术的直接施放奖励为 0，现有战后评级仍可能为本场使用过的它提供 2/4/6 点，不因新 trigger 自动消失。
- 可利用的增长方式：无限拖战、反复低风险事件、训练/任务奖励及达到上限后的行为。存在就如实记录，不在单技能修复中暗加全局限制。

幻身术本次作者目标为正常专精使用约 60–100 场到 5 级，曲线 0→5 合计 800。假定每场实际干扰得到 6 点，加已领取评级 2/4/6 点，约需 100/80/67 场；无评级约 134 场。该频率不是实测分布。此算例记录在[幻身术设计](../../proposals/battle/skills/mage_blur.md)，可复用触发、奖励、频率、成本的评估结构，不能将它的场数或曲线推广为全部技能价格表。现有 `assess_skill_power.py` 只计算战斗日程，不自动推导练习频率。
