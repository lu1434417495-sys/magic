## 1. 目标和范围

让新玩家在一次成长循环中理解四件事：我现在会什么；怎样使用这些能力；下一次人物成长还差什么；成长之后怎样调整打法。

第一段旅程的结束条件是：玩家完成首次晋升，理解本次获得的收益，并能选择继续强化旧技能或培养下一项成长技能。首次战斗是学习操作的体验节点，不新增“必须先打过首战才能晋升”的规则。

本稿提出体验方案和实施边界。本次仅增加本文档，未修改角色、技能、任务、存档或界面实现。

## 3. 推荐的组织方式

| 方案 | 玩家经历 | 状态与改动 | 主要问题 |
| --- | --- | --- | --- |
| A. 固定教学开局 | 固定技能、武器与教学战，按统一顺序成长 | 新开局内容配置与世界教学链，角色仍由现有 owner 保存 | 容易验证，但显著改变随机开局定位，分支自由度降低 |
| B. 随机候选中选择起始能力 | 玩家从有限候选中选择，之后进入教学 | 建卡候选与提交新增选择，需整体决定候选池和初始等级政策 | 玩家更有控制感，但增加建卡决策，不能仅靠三张卡片解决可用性 |
| C. 根据实际角色给出成长引导 | 保留当前起始结果，显示能做什么、缺什么，再指向已存在或补充的获取路线 | 新增只读成长目标投影，接入人物窗口和现有世界入口；内容缺口另作明确切片 | 查询需正确解释不同技能/职业条件，不能伪造可达路线 |

推荐先做 C。成长目标按当前角色事实计算，起始随机是否增加玩家选择单独讨论。不能为了让流程图整齐，降低已获得的技能等级或增加首战锁。

```text
建卡确认 → 查看起始能力 → 选择当前想发展的方向
                              ↓
                有完整晋升方案 ──────────→ 现有晋升入口
                              ↓ 否
          查看缺少的技能 / 练习门槛 / 其他职业条件
                              ↓
          找到来源 → 获取或练习 → 查看结果 → 重查条件
                              ↓
             确认晋升 → 查看收益 → 配装与下次成长目标
```

首次战斗、补给和招募穿插在这条循环中；它们不是所有人物都必须按同一顺序通过的领域门禁。

## 4. 逐步玩家旅程

### J1. 创建人物：理解身份与实际能力基础

- **进入条件**：从登录入口选择世界并开始建卡。
- **玩家操作**：逐章确认姓名、基础属性、种族/亚种、年龄和身份选项。
- **当前反馈**：身份预览与最终属性预览已有。不同身份的收益从正式内容和属性投影读取。
- **建议调整**：每章以简短文字说明当前选择影响的能力；最终确认摘要保留姓名、身份、最终属性及关键特性，详细规则按需展开。起始随机技能在现有建档阶段产生，不能在建卡确认页凭空预览一个还没确定的结果。
- **完成条件**：创建成功，主角数据、技能、武器和资源已经形成正式状态；随机授予只执行一次。

### J2. 首次出发：让玩家知道现在能怎样行动

- **进入条件**：世界初始化完成，正式角色状态已可读取。
- **玩家操作**：查看一次起始能力摘要，然后自由进入地图或人物详情。
- **建议反馈**：展示当前主攻技能、辅助能力、武器、关键资源与恢复方式；说明“人物 0 级，尚无职业，可通过技能成长取得职业”。能力不足时展示具体原因和实际可用替代行动。
- **建议入口**：世界中的简短出发提示可关闭，完整内容在人物概览保留。不要再增加一组必须逐个确认的窗口。
- **完成条件**：玩家能指出至少一种当前合法的战斗行动。该条件是体验验收，不作为禁止出发的额外限制。

起始可用性需要在最终身份和资源应用后消费正式战斗预览/规则查询。当前按标签配武器、仅对 MP 做支持，不能替代完整的可用性判定。若某些随机结果只能提供辅助能力，应明确展示可用的基础攻击方式，而非假装该随机技能一定是主攻技能。

### J3. 找到第一个目标：分清遭遇与任务

- **进入条件**：人物进入世界，相关 NPC/服务已被发现且实际可交互。
- **玩家操作**：接取适合当前队伍的目标，查看目标位置或探索线索，选择出发。
- **当前可复用内容**：初阵及村长 NPC 任务入口；附近遭遇生成；现有任务进度。
- **建议调整**：目标展示敌人/物品、数量、奖励对象和收益。对初阵如实写“荒狼 0/3”，不把“一次胜利”当任务必然完成。
- **完成条件**：玩家知道一次行动怎样推进目标，地图只指向已发现的真实来源，不泄露未探索世界的完整内容。

首战建议选择少量、行为清晰、具有退让空间的敌人，让移动、攻击和资源消耗都能被观察。具体敌人数、强度和地形需要在单人新档实测后确定，不能因生成了附近遭遇就宣称教学战成立。灰烬交界须单独验证其固定内容入口，不套用普通世界的附近遭遇保证。

### J4. 第一次战斗与结算：看见行动造成的结果

- **玩家操作**：移动、观察技能预览、选择目标、执行技能，根据资源余量决定下一步。
- **建议反馈**：把命中/效果、实际资源消耗、熟练度增量和技能升级结果关联起来；战后摘要按技能归并真实成长，再连接下一目标。
- **必须保留的规则**：技能使用不必然获得熟练度。重击使用的默认高伤害骰成长规则要求有效伤害/吸收并满足高骰事件；守御的受击成长有专用入口。引导文字不能写成“每放一次固定 +1”。
- **零增长时**：说明该技能的实际成长触发方式，仍展示本场真实贡献；不能为让提示好看而在 UI 发放隐藏熟练度。
- **受伤或资源不足时**：保留人物资源详情与已发现的恢复/补给入口；不能设计必须先花光资金买两本书、然后无力恢复的前期预算。

依据：[BattleSkillMasteryService](../../../scripts/systems/battle/runtime/BattleSkillMasteryService.cs)、[重击配置](../../../data/configs/json/skills/warrior_07.json)。本稿没有实测胜率或每场收益。

### J5. 明确成长目标：同时展示数量与练习门槛

- **进入条件**：人物窗口可打开，无需先满足晋升条件。
- **玩家操作**：查看当前可发展的职业，选择一个方向查看详细条件；查看本次可培养的技能。
- **建议位置**：人物职业页的“下一次成长”，技能页提供“距下一等级”和“距基础成长门槛”。已有完整方案继续由现有晋升按钮承接。
- **建议反馈**：分项展示资格技能、成长触发、知识/属性/声望/职业依赖；已达成与缺少项同时保留。
- **完成条件**：玩家知道接下来应取得新技能、继续练某项技能，还是补齐其他条件。

假设玩家选择战士方向，当前只有重击和另一项合法近战资格技能，且重击处于 1 级、本级熟练度 40，建议文案如下。数值来自本例状态，不是固定教学进度：

```text
战士 · 首次晋升
近战资格技能：2 / 3
本次成长技能：重击 Lv.1 / 基础门槛 Lv.3
距离下一等级：还需 210 熟练度（当前 40 / 250）
距离基础门槛：还需 760 熟练度
下一步：补足 1 项合法近战技能，并继续练习重击
```

计算按当前等级、当前级熟练度及后续曲线求剩余值；不能用 `total_mastery_earned` 代替当前等级事实，随机开局可能已有等级而历史熟练度为 0。重击从 0 到 3 级为 `100 + 250 + 550 = 900`；这不是 900 次施法，也不是人物经验值。

若另一个未消费技能已经达到门槛，界面应允许选择它，不要求补练重击。`weapon_training` 标签技能不能成为晋升触发；来源、融合、归属和支持技能条件仍需完整判断，不把“标签数量”当最终提交资格。

### J6. 补齐技能：让来源真实可达

- **当前缺口**：现有书籍生成/学习接口、任务授技、研究各自存在，但没有在本次核对中形成一条覆盖所有随机开局的基础技能来源指引。正式商店当前没有技能书。
- **建议玩家操作**：从成长目标进入已发现的学习来源；查看目标成员、技能作用、学习条件、成本，再领取或购买并学习。
- **内容建议**：为前期建立两次有明确用途的基础学习里程碑，每次提供一项尚未掌握的基础能力，分别补防御和短位移等打法需求。优先复用现有 NPC/任务板、击败目标或提交物品事件，具体提供者、目标与预算随内容切片落定。
- **例子候选**：守御和后撤步均标记为 `basic`，可用于重击示例的防御/位移补充；它们不是限定所有角色必须学习的两项技能。已有守御任务在狼王之后，新路线若前置该能力，必须同步审视旧任务的重复奖励。
- **重复情况**：候选应过滤已学技能；若无新技能可选，明确提供有价值的已学技能成长或循环资源。这个选择/替代机制是建议新增行为，当前不能按已实现描述；领奖时须再次检查。
- **完成条件**：正式学习状态已经写入，人物目标立即重新计算。仅拿到书、仅把奖励放入待领队列，不能显示为已学。

前期奖励不默认授予裂甲斩等 `intermediate` 能力，不绕过学习门槛。默认主角从 `PartyState` 的正式身份解析，不能把 `hero` 当作无条件有效 ID，也不能引入历史 ID 别名。若新路径需要可选择/动态目标的 reward 定义，应先给出严格字段与事务设计，不在窗口临时替换目标。

### J7. 首次晋升：理解选择与实际收益

- **进入条件**：已有完整合法方案；自动提示或人物按钮/G 打开。
- **玩家操作**：比较成长技能与职业，确认或暂缓；支持组合由领域求解并完整展示。
- **当前可复用反馈**：目标职业阶数、成长技能、核心/资格技能、生命骰公式、授予技能；世界和战斗共用确认链。
- **建议补充**：把本次触发技能的属性成长进度、技能上限变化和成长机会消耗说明集中呈现；确认后展示正式结果的前后差异。
- **完成条件**：人物等级 +1，所选职业阶数 +1；该技能成为核心且记入唯一晋升历史；其他支持技能不被自动变成核心。

战士例：重击触发首次晋升，生命基础增量按 `max(1, 1d10 + 2 × 体质修正)` 结算，增加力量成长进度 40、体质成长进度 20，并授予“强健”。成长进度不等于基础属性直接 +40/+20；强健的纯人物生命加成与体力恢复加成还会影响有效结果，最终 HP 应读取正式结算快照。

“迈向正职”成就另有力量 +1、生命上限 +5 的奖励，应按实际领取状态单列来源，不合并成每次战士晋升的固定收益。预览不掷骰；保存失败按现有持久化结果提示，不能重新晋升或重掷。

### J8. 晋升后配装与再出发

- **玩家操作**：查看新增能力，比较当前装备与候选装备，再决定继续强化重击或培养下一项成长技能。
- **建议反馈**：分别展示属性变化、技能可用性变化与重要特性；不存在通用“战力分数”也能说明换装价值。仓库不足、槽位冲突、需求不满足时显示正式原因。
- **当前边界**：世界队伍装备入口与战斗内换装是不同入口，不把世界队伍窗口设计成战斗期间可打开。
- **成长解释**：重击完成晋升后可从 3 级继续练到扩展上限，但它不能再推动一次人物升级；下一次晋升需要新的未消费技能，并满足该职业下一阶条件。
- **完成条件**：玩家能说明本次成长改变了什么，并确定下一项可执行的目标。

## 5. 一个完整示例与必要分支

示例人物为成年普通人类，玩家选择近战成长方向。固定重击为 0 级；随机技能按实际结果显示，本例假设它不补足所需的其他近战资格。初始武器仍须通过实际可用性检查，不能根据玩家口头选了“近战”就假设已有长剑。

| 顺序 | 玩家操作 | 预期结果与状态 | 当前/建议 |
| --- | --- | --- | --- |
| 1 | 完成建卡并查看出发摘要 | 单人、无职业，能理解重击与随机能力的用途 | 建档已有；摘要待补 |
| 2 | 选择查看战士成长方向 | 看见近战资格数量及重击门槛，知道还需扩展技能组合 | 详细缺额待补 |
| 3 | 接初阵并参加适合的遭遇 | 逐个推进荒狼计数，观察重击效果与实际成长 | 任务已有；首战适配待实测 |
| 4 | 完成并领取初阵奖励 | 50 金与重击熟练度 80 经现有奖励流到账 | 已有；不保证仅靠此奖励升级 |
| 5 | 完成两次基础学习里程碑，掌握守御与后撤步等合法支持技能 | 三项近战资格齐全，能尝试进攻/防御/位移 | 本稿提出的前期可达来源待设计实施 |
| 6 | 继续战斗与领取适用奖励，将重击练至 3 级 | 从 0 级累计跨越 900 熟练度门槛；实际时间待测 | 成长规则已有 |
| 7 | 确认重击推动战士首次晋升 | 人物 1 级、战士 1 阶，展示真实收益与强健 | 提交已有；收益呈现可补 |
| 8 | 检查装备与后续目标 | 继续练重击获取战斗收益，或培养新的成长触发技能 | 基础入口已有；目标串联待补 |

这个例子是推荐体验，步骤 5 的新来源尚不存在，不能作为当前可玩攻略。

必须覆盖的分支：

- 随机技能已达门槛：优先显示缺少的其他条件，允许它直接成为合法晋升触发。
- 随机技能非近战：保留其玩法价值，玩家可以改看其他职业；不强制用初阵奖励锁定战士路线。
- 技能奖励已掌握、达到上限或已用于成长：区分三种状态，显示实际新收益，不能反复发放空奖励或恢复已消费机会。
- 暂缓、被其他窗口打断、读档：复用现有晋升提示规则；新成长目标查询从持久角色事实重建。
- 首战失败、死亡或资源耗尽：走现有死亡/恢复规则，目标不能在死亡角色上继续提出可提交晋升。
- 不同世界预设：首次 NPC、目标来源和补给可达性分别验证。

## 6. 招募入队分支

推荐招募出现在玩家已经理解单人行动、开始看见角色能力缺口之后。是否安排在首次晋升前，需根据单人战斗压力决定，不把招募设置成晋升必要条件。

| 步骤 | 玩家看到和决定的内容 | 状态要求 |
| --- | --- | --- |
| 遇见候选人 | 来源、身份、当前技能、装备、资源与招募条件 | 候选人不是已入队成员 |
| 比较作用 | 对照现有队伍说明可补充的能力，如治疗或远程手段 | 由真实技能解释作用，不凭职业名称承诺能力 |
| 确认招募 | 一次性费用及确实存在的其他条件；余额不足明确提示 | 新增成员与扣费应形成完整事务 |
| 安排编成 | 有空位时可上阵，满员时明确进入替补或选择调整 | 最多 4 人上阵，主角保留上阵，不能静默踢人 |
| 入队整备 | 查看物品归属和技能可用性，按共享库存调整装备 | 队友可用性不能依赖玩家未持有的装备 |
| 首次协同 | 通过一场正常遭遇观察角色分工 | 不要求新增固定职业专属 AI 特例 |

当前只确认编成部分已实现。候选生成、价格、招募事务、独立成长初始状态和提示都需单独设计；本稿不假设已存在维护费、好感度或契约期限系统。

## 7. 实施边界与最小切片

### Current Ownership

- `PartyState` / `PartyMemberState` / `UnitProgress` 保存人物、队伍、技能及晋升事实。
- `CharacterManagementModule` 是成长查询与写入桥；`ProgressionService`、`ProfessionRuleService`、`PromotionEligibilityRules` 和 `SkillEffectiveMaxLevelRules` 拥有规则。
- `GameRuntimeFacade` 及现有提示/奖励 sidecar 编排窗口；`PartyManagementWindow` 等只呈现数据与提交意图。
- 任务由 `QuestProgressService`、任务 journal 和现有奖励/持久化链结算；技能学习经正式 gateway，装备经 `PartyEquipmentService`。

### Recommended Design / Minimal Slice

建议第一实现切片完成 J5“下一次成长”：

1. 增加只读、typed 的职业成长目标查询，返回当前/需求数量、可用触发技能、剩余熟练度和具体失败原因。现有 `GetPromotionOffers` 保持完整合法方案语义，不向它塞入半成品方案。
2. 缺额判定复用正式标签、来源、职业和晋升规则；闭集原因用 enum 与明确 DTO，如 `PromotionRequirementProgress`、`SkillMilestoneProgress`，名称为建议。
3. 职业页展示未达成条件；技能页展示下一等级与基础门槛；已就绪时进入现有晋升流程。
4. 初版只链接已确认存在、已发现的学习来源。没有来源时明确作为内容缺口处理，不能给出一个可点击但无效的商店入口。
5. 查询在人物页打开及成长/条件变化时刷新；不每帧枚举组合。候选选择可为会话展示状态，读档重新计算，不新增经验池或持久化资格缓存。

第二切片补 J2/J4 的出发与战后结果摘要，第三切片补 J6 的前期学习来源与领取闭环；这三片共同完成推荐旅程。第一片完成只表示“玩家看懂目标”，不能据此宣称完整可达性已解决。

## 9. 本轮证据与讨论决策

本轮完成当前源码、JSON 配置与测试源读取，计算重击门槛及示例剩余熟练度，未运行游戏、构建、Godot 回归、全套测试或 CI。

技能内附的旧任务审计脚本本次输出 `quest_count=0`、`indexed_skill_count=0`，不能用作当前 JSON 内容审计通过证据。本稿直接读取正式 JSON 目录和运行时入口；没有将旧 `.tres` 目录的空结果视为无问题。

建议按以下顺序讨论：

1. 先认可“按实际状态显示下一次成长”的主流程与缺额信息。
2. 决定前期基础能力是通过任务里程碑、据点教学或正式商店提供，并给出每个来源的预算和重复获得政策。
3. 用自然新档确认时间与难度，再决定随机技能初始等级、有限选择和熟练度节奏是否调整。
4. 单人循环明确后，确定第一位队友出现时机与招募内容。
